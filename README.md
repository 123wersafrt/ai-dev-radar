# AI Dev Radar · Web 端

追踪 AI 开发世界的每一次变化。**只自研「变化层」**——底层数据全部复用成熟开源项目。

## 立即打开

双击 `index.html` 即可（数据已内联在 `data.js`，`file://` 直开不受 CORS 限制，无需起服务器）。

## 功能

| 页面 | 做什么 |
|---|---|
| **今日情报** | 今日高/中/低影响变化统计 · 14 天趋势（柱高＝变化量，柱色＝高影响占比）· 最值得关注 |
| **变化流** | 7,679 条价格变化，可按时间/影响等级/计量指标/平台筛选 + 搜索 + 分页 |
| **我的关注** | 关注模型后自动汇总其所有变化（跨数据源打通） |
| **价格比较** | 按你的实际用量算月成本，而非只看单价；可限定主流厂商/对话模型 |
| **模型库** | 7,320 个模型 · 180 个 provider，按用途分类（对话/向量/语音/图像/视频…） |
| **API 状态** | 聚合 OpenAI / Anthropic 官方状态页 |

## 核心：影响判断

每条变化的影响等级由四件事决定，而不是简单阈值筛选：

- **调整幅度**（分档：≥300% / ≥100% / ≥50% / ≥20% / ≥10%）
- **方向**（涨价对成本冲击高于降价）
- **厂商权重**（主流厂商调价影响面更广）
- **计量指标**（输入/输出才是成本主体，缓存读写权重更低）

输出不是「涨了 50%」，而是「**你要不要动**」+ 具体建议。

## 配色

深色控制台，暖棕底 + 琥珀强调（保持原色系，修正搭配）。所有配对经 ΔE00 + APCA 双指标校验，**42 项全部通过**（脚本：`_audit/verify-final.py`）。

关键修正（原配色 23 项中 17 项不达标）：

| 问题 | 原值 | 修正 |
|---|---|---|
| 表面层糊在一起（card/bg ΔE00 仅 4.04） | 靠色相区分 | 改**靠明度 + 可见描边**（line vs card ΔE00 9.2） |
| 弱文字不可读（Lc 27 / 14） | tx3/tx4 | 提亮到 Lc 48.6 / 43.4 |
| 色相太多且互相撞色 | amber/terra/yellow 三色 ΔE00 仅 6.4 / 6.1 | **色相 5 → 3**，只留琥珀 / 红 / 绿 |
| 状态色当正文用（砖红在深底 Lc 上限仅 35，物理不可能达标） | 彩色文字 | 改**色条 + 中性底标签**；彩色文字走「浅底深字」pill |
| 同色重复铺 | 色条+标签同红 | 色条承担等级，标签改中性底 |

**语义色分工**：琥珀＝品牌/中影响，红＝高影响/涨价，绿＝低影响/降价。红绿为色盲对，故状态**不单独用颜色表达**，始终配文字标签。

**大字专用色**：`--red-lg` / `--green-lg` 是 red/green 的提亮版，仅供 25px+ 大数字（需 Lc≥60）；色条/色点仍用原色（需 Lc≥45）。

## 更新数据

```bash
python refresh.py
```

需要本机代理（默认 `http://127.0.0.1:7890`，可用环境变量 `RADAR_PROXY` 覆盖）。
脚本会重新拉取全部数据源 → 归一化 → 重算影响判断 → 生成 `data.js`。刷新页面即可。

## 文件说明

```
index.html     单文件应用（UI + 逻辑，无构建步骤）
data.js        数据（由 refresh.py 生成，勿手改）
refresh.py     一键更新数据
raw/           原始数据缓存（models.json / price_changes.csv）
verify.mjs     Playwright 自动验证脚本（截图 + 探针）
_shots/        验证截图
```

## 已知边界

- 价格数据**仅含标准计费**，不含缓存命中、批处理等折扣；models.dev 为社区维护，对外发布前建议二次校验。
- 关注列表存在浏览器 `localStorage`，换设备不同步（无后端）。
- 状态页目前只接了 OpenAI / Anthropic；扩展端点见 ai-status-hub 的 `services.json`。
- 趋势柱为「高影响占比」着色，阈值 22% / 15% 是按当前数据分布定的，数据量级变化大时需要重调。
